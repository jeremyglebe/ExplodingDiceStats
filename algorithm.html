The node contains everything needed to decide what happens next.

  • Dice + results define the new branches: only maximum results explode.
  • Path probability is this roll’s chance multiplied by its parent’s probability.
  • Total + target test decide whether the branch has already succeeded.
  • Termination reason is one of: target reached, no explosions, or continue.

Pruning

Most branches end immediately.

SUCCESS TERMINAL total ≥ target

Record this node’s path probability. Do not roll again—even if one of its dice exploded. Positive rerolls cannot undo success.

FAILURE TERMINAL total < target
and no active dice

There is nothing left to roll. This branch can never change, so return immediately.

Recurse only when total < target and at least one die exploded.
The data model

The graph is a directed result tree.

  • ROOTtotal 0

Nodes
The complete result state recorded after one roll combination.
Directed edges
Every possible next combination rolled from the parent node.
Edge weights
The local chance of that combination; multiplied into the parent’s path probability.
Leaves
Terminal success or failure nodes with no children to explore.

Every node has exactly one parent and one recorded history. No branches are merged.

Efficiency—or the lack of it

This is brute force.
Tabletop inputs are tiny.

1

Enumerate everything reachable

There is no shortcut here: the search explicitly visits every roll combination that can still matter.

2

Scaling gets ugly

More dice, larger dice, and higher targets multiply the branch count. At large scale this becomes horrendous.

3

Pruning rescues real rolls

Success stops a subtree, ordinary non-max rolls stop failures, and only exploding dice continue.

4

The domain stays small

Tabletop pools are a handful of d4–d12 dice and targets in the tens—not millions of dice or enormous totals.

It is acceptable because the problem domain is constrained—not because brute force suddenly became efficient.

Combining the terminal successes

Find the chance that none of them occur.

01Collect success nodes

Each “target reached” node carries its complete path probability pᵢ.

02Flip each probability

The chance of that individual result not occurring is 1 − pᵢ.

03Multiply the non-results

Multiply every individual non-occurrence chance together.

04Flip the combined result

Subtract from 100% to get the chance of at least one success.

P(no success result) = ∏(1 − pᵢ) P(success) = 1 − ∏(1 − pᵢ)

This is the final aggregation performed by the original Python implementation.

The complete idea

The algorithm is recursive enumeration with pruning.

search(state):
  active = dice_that_exploded(state)
  if active is empty: return

  for rolls in all_combinations(active):
    child.total = state.total + sum(rolls)
    child.p = state.p / combination_count

    if child.total >= target:
      record child.p
    else:
      search(child)

none = 1
for p in recorded_probabilities:
  none = none * (1 - p)

success = 1 - none
